# 公式記録の同期失敗（2026-11-12）

全選手の同期で「取得できる公式記録がありませんでした」と表示されるとの報告を受けて調査。稼働中jasf-test v9への読み取り専用の1要求では、プロキシHTTP 200・success=false・公式側status=403・本文空を確認した。関数のHTTPコードだけでは取得成功を判定できない。

既存フロントは公式側statusを無視してHTTP 200というエラーを作り、全条件が失敗するとそれを「記録なし」に上書きしていた。また全条件のPromiseを先に作り、全て同時取得していた。

## 修正

- 公式側statusを読み、401/403/429の制限、サーバー異常、不正な応答、通信失敗を区別する。失敗時の表示をエスケープする。
- 同期は1条件ずつ、条件間を1.5秒空けて取得する。制限・サーバー障害・通信失敗で停止し、自動再試行しない。同時の二重同期も防ぐ。
- 正常応答のresult配列が空の場合だけ記録なしとして扱う。全要求失敗を競技者ID/年度の誤りと表示しない。
- 一部だけ取得できた場合は部分同期と明示し、制限が出た後のラップ取得は保留する。全選手更新も失敗を成功として数えず、制限時は残りの選手への取得を停止する。
- 取得失敗を理由に既存記録を削除・更新しない。DBスキーマ、競技者ID、既存JO判定、手入力ラップの保存・置換ルールは変更しない。

公式側のアクセス制限そのものは解除できていない。この修正は取得成功を保証するものではない。IP切替や別経路による制限回避、認証情報の取得などは行わない。取得可能になるまでは既存の手入力・スクリーンショット登録を利用する。

## 検証

`node tests/official-sync-errors.cjs`：HTTP 200内の公式403/429/401の判別、最初の制限で停止、逐次取得、空結果と通信異常の区別、不正JSON/スキーマ、二重同期防止、部分同期、全選手停止、取得失敗時の書き込みなしを検証する。manual-lap-preservationとanalysis-uiも成功。
