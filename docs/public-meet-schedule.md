# QRページの本人の大会予定

東京SC招待の出場種目を、既存の個人QRページの出場予定欄に日別・競技番号順で表示する。対象は2026年10月30日〜11月3日の第57回大会。予選またはタイム決勝の番号を表示し、区分決勝・決勝は進出時のみ出場する旨を添える。種目のない日は表示しない。

公開APIは既存の共有トークン検証、公開ON・同意確認済み・活動中の確認後に `getPublicMeetSchedule` を呼ぶ。本人が出場選手に登録された大会のうち、対象大会の本人の種目だけを取得する。申込タイム・クラス・備考・他選手一覧・選手IDは予定情報に含めない。生年月日やPDF原本も含めない。参加者登録を外せば、その大会の種目もQRに返さない。

日程は管理画面と同じ `meet-schedules.js` を利用し、開催中も最終日まで大会を表示する。APIの日付判定は日本時間。出場種目の追加・変更はコーチの大会欄から行う。既存のQRリンクは継続使用できる。

検証：`node tests/public-meet-schedule.cjs`。本人別の取得、共有トークンの無効・停止・同意なし・非活動、他人のIDをリクエストに足した場合、参加削除、開催期間の境界、日別順序、空・未照合・HTMLエスケープを確認する。既存のPDF・競技順・ラップ・ランキング・分析のテストも実行する。

デプロイは既存 `swimmer-public-profile` の `verify_jwt=false` を維持する（関数内の共有トークンによる認証）。`meets.ts` を関数ファイルに同梱し、既存のlaps.ts・共有基準表も維持する。DBスキーマ・RLS変更は不要。

秋季大会を含む他の出場予定大会も、本人の登録種目と水路を表示する。競技順の定義がない大会では日別・競技番号を推測しない。本人の参加大会に絞って種目を500件単位で取得し、返却時に大会ID・選手ID・申込タイムを種目から除外する。

## プログラム・予定時刻（2026-11-07）

本人の出場種目の内部IDだけを使って `swim_meet_programs` を読み、競技日・競技番号・ラウンド・組・レーンを公開用の必要項目へ変換する。予定表は参加大会だけを取得し、性別・泳法・距離・水路・日付・ラウンド・競技番号で照合する。男子に公式時刻がない場合は、同じ条件の女子時刻＋2分を「目安」として表示する。女子候補が複数ある場合や日をまたぐ場合は補完しない。

公開レスポンスに選手ID・種目ID・参加者一覧・申込タイム・PDF名・出典・クラスは含めない。既存の公開ON・同意・活動中・共有トークン検証を維持する。共有停止や参加解除により表示対象から外れる。QRの再発行は不要。

QR画面は日付・競技番号順。組・レーン登録前でも予定表があれば時刻を表示する。既存の東京SCの競技順による表示は、実プログラムがない場合のフォールバックとして残す。

配備順: `supabase/setup/qr-meet-program.sql` によるservice_roleへのSELECT付与→稼働中の5ファイルを維持したswimmer-public-profile個別配備→フロント公開。既存のverify_jwt=falseを維持し、関数内部の共有トークン認証を変更しない。anon/authenticatedの権限・RLSは変更しない。

追加検証: 他人の出走行の除外、本人IDへのIN絞り込み、内部ID/PDF名/申込値の非返却、公式時刻優先、男子＋2分、No.32と原表No.31重複の分離、表示順、HTMLエスケープ。Chromiumで390pxのQR表示・横はみ出しなしを確認。公開同意のある本人の実データをトークンなしで読み取り、同じAPI集約関数に渡して2件の組/レーンと2件の目安時刻を確認した。実共有トークンの取得は自動承認レビューで拒否されたため行わず、認証ゲートはテスト用トークンで検証。公開エンドポイントの無効トークン応答も確認した。
