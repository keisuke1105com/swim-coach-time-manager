# 大会の出場種目とPDF取込

大会カードの「PDFから種目を追加」でWebSWMSYSの「個人種目申込一覧表」を選択する。
大会の水路を選び、登録先・選手・種目・申込タイムを確認して保存する。
文字を選択できるPDF、10MB以下・50ページ以下・1000種目までに対応する。画像PDFや他の様式は取り込まない。

PDF.js 4.10.38を必要時のみ読み込み、端末内で文字と位置を抽出する。
PDF原本や生年月日は送信せず、照合済み選手の内部IDと申込種目・原表記だけを保存する。
氏名の全半角・空白を正規化し、同姓同名・生年月日・性別の不一致を自動登録しない。
未登録選手は選手一覧で登録してからPDFを読み直す。

大会水路と申込元の水路を分離する。S・L・＊は `entry_mark` に保持し、
申込タイムを `swim_records` に追加したり、自己ベストとして判定したりしない。
既存の種目とタイムは保持する。同じ申込値で原表情報が未入力のときだけ補完する。
同じPDFを再取り込みしても複合ユニーク制約で重複しない。

クラスは大会固有の表記を保持する。「17・18歳」「14歳」「小学生」「一般」等に対応し、東京SCの6区分には限定しない。
空のクラス・60文字を超える値・制御文字・複数種目が混入した行は登録しない。
既存環境は `supabase/setup/meet-entry-class-labels.sql` で保存側の区分チェックも更新してからフロントを公開する。

## 反映

1. `supabase/setup/meet-entry-pdf.sql` を対象プロジェクトに適用する。
2. `index.html`、`meet-entry-pdf.js`、`meet-entry-import-ui.js` を同時に公開する。
3. コーチとして大会欄を開き、既存の種目表示とPDFの確認画面を確認する。

保存は `import_swim_meet_entries` の1回のRPCで、参加者・種目を同一トランザクションに登録する。
関数はSECURITY INVOKERで既存のコーチ用RLSに従い、未ログインでは実行しない。
関数実行権限はauthenticatedのみ。共有QR画面・公開関数には変更を加えない。

## 検証

`node tests/meet-entry-pdf.cjs`

今回の実PDFでも2ページ・21名・41種目、S30件・L8件・＊3件を確認する。
山梨県秋季大会の添付PDFの抽出テキストでも2ページ・26名・56種目を照合済み。
認証ロールで56種目の保存・再取込の重複防止・長すぎる区分の拒否を検証し、トランザクションをロールバックして既存データを保った。
実PDF・実選手のテスト用データは公開リポジトリに含めない。
