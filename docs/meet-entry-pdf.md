# 大会欄の種目表示とPDF取込

大会カードの「PDFから種目を追加」からWebSWMSYSの「個人種目申込一覧表」を選択する。
大会の水路と、選手・種目・申込タイムを確認して登録する。
文字を選択できるPDF、10MB以下・50ページ以下・1000種目まで。画像PDFや他様式は対象外。

PDF.js 4.10.38を必要時に読み込み、端末内で解析する。
PDF原本と生年月日は送信せず、照合済み選手の内部IDと申込種目・原表記のみ保存する。
氏名の全半角・空白を正規化し、同姓同名・生年月日・性別の不一致は自動登録しない。
未登録選手は選手一覧で登録してPDFを再選択する。

大会水路とは別にS・L・＊をentry_markへ保存する。
申込タイムをswim_recordsや自己ベストに追加しない。既存の種目・申込タイムは上書きしない。
同じ申込値で原表情報が未入力のときのみ補完する。

保存はimport_swim_meet_entriesの1回のRPCで参加者・種目を同一トランザクションに登録する。
SECURITY INVOKERで既存のコーチ用RLSに従い、authenticatedのみ実行可能。
共有QR画面・公開関数は変更しない。

反映はsupabase/setup/meet-entry-pdf.sqlを先に適用し、index.htmlと追加JS2ファイルを同時に公開する。
今回の既存21名41種目にも原表情報を補完済み。件数・申込タイムは保持した。

検証:
- 実PDFをPDF.jsで解析：2ページ・21名・41種目、全行照合。S30件・L8件・＊3件。
- 認証済みロールで41件の追加、21名の参加登録、再取込0件追加、不正値時のロールバックを確認。
- node tests/meet-entry-pdf.cjs
- 既存のanalysis-ui、jasf-ranking-fallback、public-rankingsも確認。
- 既存analysis-rankingsの「あと 5.00秒」期待値は変更前mainでも同じ失敗を再現。今回の変更では修正していない。
実PDF・実選手のテスト用データは公開リポジトリに含めない。
