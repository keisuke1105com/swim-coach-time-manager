# スクショ取込の確認フロー

画像のOCRは既存のTesseractを利用して端末内で実行する。公式サイトへの通信は行わない。

1. 画像を選択して解析する。読み取れない項目は手入力できる。
2. 大会名・競技日を入力し、各候補の選手・種目・距離・水路・今回のタイム・通過タイムを画像と照合する。
3. 保存対象と画像照合のチェックを行い、「保存内容を確認する」を押す。
4. 最終確認画面の「確認して保存」で初めてDBへ追加する。

候補は初期状態では保存対象にしない。水路・日付・欠けた分は推定しない。角括弧内のベストタイムやRTを今回のタイムとして取り込まない。選手名の不一致は保存を止め、OCR誤読の修正または登録先の再選択を求める。修正・画像変更・キャンセルは最終確認を無効化し、古いOCR結果も採用しない。

ラップ入力は「50m 30.12」の形式で、50mから順番に通過タイムを指定する。画像にない25m地点は生成しない。保存先は既存の `swim_records.laps`。手入力の `swim_manual_laps` と既存の公式ラップには書き込まない。スクショ由来の速報として追加し、同一選手・日付・種目・距離・水路・タイムの完全一致はスキップする。既存記録の削除・置換はしない。

保存成功後だけ既存のベスト印再計算を実施する。複数件の途中で失敗した場合は保存済み件数を示し、再確認を求める。再実行時にも完全一致の重複をスキップする。QR表示は既存の記録・ラップ表示経路を利用する。

検証: `node tests/screenshot-import.cjs`、`node tests/manual-lap-preservation.cjs`、`node tests/public-manual-laps.cjs`、`node tests/analysis-ui.cjs`、`node tests/official-sync-errors.cjs`。

保存直前・保存後のクラウド再読込は厳格モードで行う。読込が失敗した場合に既存記録を空とみなして追加しない。保存直前には登録先選手がまだ存在することも再検証する。

ブラウザ検証: `node tests/screenshot-browser.cjs`。Chromiumで390px/1280pxの幅を検証。CIではPlaywright 1.62.1を一時ディレクトリに導入し、ChromiumとWebKitで実行する。OCR結果・保存処理・データは合成データとモックに限定し、確認前・キャンセル・修正時の保存防止、保存失敗、読込失敗時の停止を確認する。

実Tesseract（jpn+eng）で合成した大会結果画像を読み取り、今回のタイム・通過タイムの認識を確認した。OCRが挿入する「自 由 形」などの空白も種目判定で許容する。CIのChromium/WebKitの390px/1280px検証も通過した。

実スクリーンショットのOCR精度、実機Safari/iPhone、本番保存は別途確認が必要。実選手のデータ更新や公式サイトへの取得は検証に使用しない。
