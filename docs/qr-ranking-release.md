# QRランキング更新の反映手順

対象はPR作成時点の `swimmer-public-profile` 稼働版v10。稼働中の目標タイムと大会予定取得を保持してGitHubのソースに同期したうえでランキングを変更した。

1. 公開直前に稼働中の関数を再取得し、v10以降の変更があれば取り込む。目標・大会予定・手動ラップを失わないことを確認する。
2. `swimmer-public-profile` だけを配備する。必要なファイルは当該フォルダの `index.ts`、`laps.ts`、`../_shared/jo-standards.ts`、`../_shared/yamanashi-standards.ts`。既存の `verify_jwt=false` と、GET時の共有トークン・有効化・同意・active確認は維持する。他の関数は配備しない。
3. 画面のmainへのマージとGitHub Pages公開を確認する。画面だけの公開では新しい県強化ランキングデータは届かない。
4. 同意済みの実際のQRページで、JO90%以上・最大20名、県強化最大20名、4つの移動ボタン、自己ベスト・目標・大会予定・ラップを確認する。
5. 共有無効・未同意・非活動の選手をランキングに含めない。生年月日・内部ID・共有トークンはランキングの応答に含めない。これらは合成データのテストでも検証する。

公開ランキングは公開同意のある選手のみが対象なので、管理者の全選手ランキングと人数・順位が異なる場合がある。県強化の2026年度基準は `yamanashi_2026.js` と一致することをテストしている。JOの判定基準日・年齢区分と県強化の4月1日時点の学年は分けて扱う。

データベースの書き込みやスキーマ変更は不要。PR作成時点ではmainへのマージ・関数配備とも未実施。
